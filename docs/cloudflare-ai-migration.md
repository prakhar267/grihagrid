# Cloudflare-first AI delivery

## Customer outcome

Owners can generate an optional planning memorandum and direct a saved camera
tour using Cloudflare Workers AI, with Google Gemini available as a disclosed
fallback. Drawing, local OCR, house geometry, walking, camera paths and export
remain deterministic and usable without a provider.

Journey: save a house → review the facts or camera stops → explicitly consent to
Cloudflare processing (optionally allow Google fallback) → validate the generated
answer → save with its actual provider (and planning model) provenance. Existing Gemini records
remain readable. Older clients must never silently authorize a new processor.

Acceptance: both remote AI routes prefer Cloudflare; fallback is opt-in and
bounded; malformed or unsafe output is rejected; identity, consent, revision,
lease and quota guards precede external work; cached results make no provider
call; a quota or outage leaves manual planning/tours available. Actual provider
checks are recorded separately from injected-provider tests.

KPI: both remote AI paths covered by the same adapter, zero undisclosed fallback
calls, zero provider calls before admission, actual provider shown on saved work.
Guardrails: no paid-plan upgrade, no new private-data transmission, no geometry
generated by an LLM, no unsupported construction/approval claims, no real customer
data changes. Continue the existing local/draft-review delivery scope.

## Provider constraints (verified 21 September 2026)

Cloudflare provides 10,000 neurons per account per UTC day on Workers Free.
Workers Paid bills usage beyond that allocation; other applications share it.
Use the allowlisted `@cf/meta/llama-3.3-70b-instruct-fp8-fast` with JSON Schema output,
bounded input/output and a conservative D1 reservation per call. Production and
staging receive separate smaller allowances. These are application limits;
Cloudflare's account plan remains the final billing boundary.

## Implementation

Both routes call `callAiJson` with their existing schema and semantic validator.
The model is allowlisted, uses a 20-second deadline, at most 12,000 UTF-8 input
bytes (including JSON Schema) and 1,600 output tokens. Each invocation reserves
700 neurons in the existing D1 counters, gated by the current project lease.
At the published rates, even 12,512 input tokens and 1,600 output tokens total
less than 700 neurons; byte counting deliberately overestimates normal input.
Production allows 5,600 neurons (eight reservations) and staging 2,800 (four).
They share the account's free allocation; these limits leave 1,600 neurons for
other usage but cannot control unrelated applications. Do not upgrade the account
or raise the limits without revisiting that budget. Cache reads are free of
inference. Failed calls retain their reservations, and the UTC window resets daily.

Gemini fallback requires `AI_GEMINI_FALLBACK=true`, a valid `GEMINI_API_KEY` and
explicit `aiProviders` consent containing `gemini`. A request can make at most
one Cloudflare call followed by one Gemini call (15-second fallback deadline),
within the existing two-attempt platform reservation. Input-size, free-quota and
transport failures can fall back. Invalid or unsafe answers cannot. With no
Cloudflare binding, only a consented configured Gemini fallback can run. No keys
are shipped to the browser. The unchanged project lease expires after 45 seconds.

New clients submit `acceptedAiTerms: true` and `aiProviders: ["cloudflare"]`, or
both `cloudflare` and `gemini`. An older Google-only checkbox never authorizes
Cloudflare. Saved briefs retain the actual model and expose its provider; saved
tours accept the new `cloudflare` source while retaining historical Gemini data.
No schema migration is needed. Both configured environments have their own AI
binding, D1 counters and provider controls. Local dev uses the account allowance;
the regular test suite uses injected providers and isolated local databases.

## Verification

On 21 September 2026 the live canary made four successful Cloudflare calls using
synthetic Jaipur/Delhi planning facts and anonymous tour references. Planning
responses took 12.54 and 11.39 seconds; direction took 1.43 and 1.56 seconds. All
passed the application's schema and semantic validators. No Gemini fallback,
deployment, remote database or customer data was involved. Run the bounded
`node scripts/check-cloudflare-ai.mjs --live` explicitly to repeat.

The live check rejected two earlier model candidates: the 8B FP8 variant returned
5025 for JSON Schema and the original 8B model returned deprecation code 5028.
The configured 70B model was selected only after the live checks succeeded.
See also the [model retirement notice](https://developers.cloudflare.com/changelog/post/2026-05-08-planned-model-deprecations/).

Automated coverage includes strict processor consent, unavailable configuration,
UTF-8 and response bounds, timeout/outage handling, one-attempt fallback, semantic
rejection, actual provider persistence and read-only cache hits. Real local D1
coverage includes both AI endpoints, saved tour validation, ownership/CSRF guards,
lease release and concurrent free-allocation reservations.

The stronger G+2 canary then generated real three-storey models for both cities,
selected an inhabited room on each floor, requested 45-second subject-aware walks,
and validated the resulting geometric tours. It exposed duplicate IDs when a
walk preference created both a travel shot and a subject hold. The hold now uses
its own shot-kind ID, with a regression covering unique shots, timing and all
three floors. The repeated live canary passed for Jaipur (4.94 seconds) and Delhi
(4.02 seconds), each visiting three of three floors. Repeat only this check with
`node scripts/check-cloudflare-ai.mjs --live --tour-only`.

Browser verification used one synthetic local Jaipur project: create G+2 brief,
review and accept geometry, use Cloudflare direction without Google consent,
save a tour revision, play through to the second-floor bedroom at 45 seconds,
generate a planning memo and reload its cached provider/model provenance. The
memo explicitly identifies the saved planning report as its source; edited house
geometry is a separate versioned record. The report passed 390px width and
keyboard consent/focus checks with no horizontal overflow or captured console
warnings/errors. Camera controls passed native Chrome 200% zoom (735px effective
viewport, matching document width), and reduced-motion operation. Temporary zoom
and viewport settings were restored. Physical iPhone and spoken VoiceOver remain
previously deferred. The account dashboard identified Workers Free as the current
plan; no plan change was made.

The final-source local gate passed all **910 tests**, including both provider
paths and the three-floor walk regression. `npm ci`, the build/Sites tests and
operational checks, all 24 fresh local migrations, production/staging Worker
dry-runs, dependency audit (zero vulnerabilities), and `git diff --check` passed.
The exact-head hosted CI and CodeQL results are recorded in draft PR #83. No
production deployment or fresh live Gemini call is claimed for this migration.
