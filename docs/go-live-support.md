# Reachable launch support

The go-live audit on 26 September 2026 found that the advertised
`hello@grihagrid.in` mailbox uses a domain returning DNS NXDOMAIN. The customer
outcome is an honest, reachable bug-report path without leaking private house
or account context to a public issue tracker.

The journey is Studio guide, footer or report concern → clearly labelled public
GitHub issues → a privacy reminder before the user writes a report. No issue is
submitted automatically, no project data is prefilled, and links suppress the
HTTP referrer. Private account support and email recovery remain unavailable
until an operator provides and verifies an inbox; a public issue is never an
account-recovery or sensitive-document channel.

Acceptance: no broken mailbox links, an accurate Cloudflare-first studio guide,
working keyboard links, readable desktop/mobile/zoom layouts, and a public issue
form that asks for generic reproduction steps without account/site information.
The KPI is zero links to the unavailable mailbox and zero automatic private-data
transfers. Preserve existing policies, payment controls and product styling.

Browser verification on 26 September 2026 covered the guide, registration and
three legal routes at 1440px and 390px, with no horizontal overflow or broken
mailbox links. Native Chrome confirmed readable support text at 390px and 200%
zoom, keyboard focus continuity and a three-page print preview containing the
support notice. Reduced-motion emulation showed no support animations or
overflow; the override and zoom were restored afterwards. Console errors were
empty. No bug report or private information was submitted during verification.

Registration now explains the unavailable recovery path before account creation.
The existing report-feedback regression check verifies the public-report privacy
warning, referrer suppression and removal of the unavailable mailbox. Private
support remains an operator setup requirement, not a completed provider check.
